# Система заказов на покупку билетов

Это проект, реализующий систему заказов на покупку билетов с использованием микросервисной архитектуры. Он состоит из двух основных микросервисов: микросервиса авторизации пользователей и микросервиса обработки заказов на покупку билетов.

## Микросервис авторизации пользователей

Этот микросервис отвечает за регистрацию новых пользователей, их аутентификацию и получение информации о пользователе. Он предоставляет следующие конечные точки RESTful API:

### POST /api/users/register

Регистрация нового пользователя. Требуются следующие параметры:
- `nickname`: отображаемое имя (ник) пользователя
- `email`: адрес электронной почты пользователя
- `password`: пароль пользователя

### POST /api/users/login

Аутентификация пользователя и получение JWT токена. Требуются следующие параметры:
- `email`: адрес электронной почты пользователя
- `password`: пароль пользователя

### GET /api/users/{userId}

Получение информации о пользователе по JWT токену. Требуется заголовок `Authorization` с JWT токеном в формате `Bearer {token}`.

## Микросервис обработки заказов на покупку билетов

Этот микросервис отвечает за создание новых заказов на покупку билетов, получение информации о заказе и обновление статуса заказа. Он предоставляет следующие конечные точки RESTful API:

### POST /api/orders

Создание нового заказа на покупку билета. Требуются следующие параметры:
- `userId`: идентификатор пользователя, который делает заказ
- `fromStationId`: идентификатор станции отправления
- `toStationId`: идентификатор станции назначения

### GET /api/orders/{orderId}

Получение информации о существующем заказе по его идентификатору.

### PUT /api/orders/{orderId}/status

Обновление статуса существующего заказа. Требуются следующие параметры:
- `orderId`: идентификатор заказа
- `status`: новый статус заказа (check, success или rejected)

## Сущности и базы данных

Проект использует следующие сущности и базы данных:

### Таблица `user`

- `id`: уникальный идентификатор пользователя
- `nickname`: отображаемое имя (ник) пользователя
- `email`: адрес электронной почты пользователя
- `password`: хешированная версия пароля пользователя
- `created`: дата и время регистрации пользователя

### Таблица `session`

- `id`: уникальный идентификатор для каждой сессии
- `user_id`: связанный идентификатор пользователя
- `token`: JWT токен для аутентификации
- `expires`: дата и время истечения срока действия сеанса

### Таблица `station`

- `id`: уникальный идентификатор станции
- `station`: название станции

### Таблица `ticket_order`

- `id`: уникальный идентификатор для каждого заказа на покупку билета
- `user_id`: идентификатор пользователя, разместившего заказ
- `from_station_id`: идентификатор станции отправления
- `to_station_id`: идентификатор станции назначения
- `status`: текущий статус заказа (check, success или rejection)
- `created`: дата и время создания заказа на покупку билета

## Технологии и зависимости

Проект использует следующие технологии и зависимости:

- Kotlin
- Spring Boot
- Spring Web
- Spring Data JPA
- Spring Security
- H2 Database (для целей разработки)
- JSON Web Tokens (JWT) для аутентификации

## Запуск проекта

1. Клонируйте репозиторий на свой локальный компьютер.
2. Убедитесь, что у вас установлены Java и Maven.
3. Откройте проект в вашей интегрированной среде разработки (IDE).
4. Настройте конфигурацию базы данных в файле `application.properties` или `application.yml`.
5. Запустите приложение Spring Boot.

После запуска приложения вы можете использовать Swagger UI или любой другой инструмент для тестирования RESTful API.
